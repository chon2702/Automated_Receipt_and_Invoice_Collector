# goco Gmail and manual import Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking. Native execution is proposed; do not start implementation before specification review.

**Goal:** Ship a Windows CLI that preserves original invoices from manual imports and Gmail and reports collection and obligation states reliably.

**Architecture:** Shared ingestion/storage and a rebuildable local SQLite index serve manual and Gmail collectors. Vendor rules share Gmail transport. Explicit obligations and portable run reports keep business completeness separate from retrieval success.

**Tech Stack:** Python 3.12+, argparse, dataclasses, JSON, SQLite, hashlib, pathlib; Google auth/client packages, keyring, defusedxml; pytest for meaningful behavior tests. Resolve current compatible versions at implementation and record them; no dependency installation during planning.

**Spec:** [MVP specification](../specs/2026-11-05-goco-mvp-design.md). Status: implementation authorized; local milestones implemented and tested, live company pilot pending.

## Global Constraints

- Python 3.12+; Windows-first; one writer process on one workstation.
- Versioned JSON configuration and reports use schema version 1.
- Gmail/Google Workspace email collection plus manual import first; AWS API next.
- No plaintext token fallback; no real documents or secrets in version control.
- Month means message received month for Gmail candidate discovery; service period requires verified metadata.
- Maximum original size: 25 MiB, configurable downward only in release 1.
- Network defaults: connection timeout 10 seconds, read timeout 30 seconds, three attempts total for transient errors, Retry-After capped at 60 seconds.
- Original attachment bytes are the primary business records; unknown metadata stays null.

## Review Focus

1. Identical bytes in different cardholder accounts must not silently transfer ownership (Task 2).
2. A valid invoice in a nested MIME part near a Berlin month boundary must not be omitted (Task 5).
3. Interrupted sidecar/index updates must remain recoverable with provenance intact (Task 2).
4. A failed mailbox scan must not produce an authoritative missing-invoice result (Tasks 3 and 6).
5. Ambiguous account routing and link-only messages must remain visible for review (Task 5).
